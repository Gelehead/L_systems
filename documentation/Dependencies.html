03 — Detailed Interactions
From To Data / Signal Notes
Client → Engine MapCommand queue Client never mutates MapState directly. All actions (tile place, generate, undo) become commands. Engine dequeues and applies them.
Engine → Client MapState front buffer (read-only ref) Client reads the front buffer every ImGui frame for display. Never sees the back buffer during generation.
Client → Renderer ImGui draw calls via ImGuiLayer Client widgets call ImGuiLayer methods. ImGuiLayer owns all Vulkan ImGui internals. Client never calls Vulkan directly.
Engine → Renderer IRenderer::BeginFrame / DrawScene / EndFrame Engine calls through the IRenderer abstract interface. Renderer owns all GPU resources. Engine never calls vk* functions.
Engine → Logic .mapbin payload (via GenerationScheduler) Engine serialises current MapState to .mapbin, passes to tile workers. Each worker calls Logic with a chunk-sized binary payload.
Logic → Engine .mapbin result payload Logic returns a binary result per chunk. Engine accumulates into back buffer via BinaryReader. Logic has no return path to Renderer or Client.
Logic → Common RegionMap::blendedInfluence() · SeedSystem::deriveTileSeed() Read-only queries. Both are stateless or immutable during phase 4. No synchronisation needed.
Engine → Serial MapState encode / decode trigger On generation trigger: BinaryWriter encodes MapState. On result return: BinaryReader decodes into back buffer. Same codec for disk save/load.
Serial → Logic .mapbin buffer (in-memory) Serialization produces the binary payload that Logic consumes. Logic never reads MapState structures directly — only the encoded binary.
Renderer → Common MapState front buffer (read-only) ChunkManager reads MapState to determine dirty chunks. MeshBuilder reads Tile data. Neither modifies MapState.
Engine ↔ Common MapState double-buffer swap (atomic) At phase 6, Engine atomically swaps front/back MapState pointers. Render thread always reads front. Generation always writes back. No blocking.
Vendor → Renderer Vulkan API · GLFW · VMA · ImGui source Vendor libs are dependencies of Renderer only (plus GLFW in Engine for window). Logic, Serialization, Common, Client have zero vendor dependencies.
Double-buffered MapState — The single most important synchronisation decision in the architecture. Generation writes into a back buffer across all 6 phases. The render thread reads the front buffer every frame without blocking. At phase 6, Engine performs a single atomic pointer swap. The render thread picks up the new state on its next frame. There is no mutex held across a frame boundary. Generation and rendering never contend for the same buffer.
